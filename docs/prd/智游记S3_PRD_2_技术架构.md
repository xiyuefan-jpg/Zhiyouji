## 0. 一页结论

| 环节 | 选择 | 为什么 |
|---|---|---|
| 服务器位置 | **中国内地**（不用香港，见第 1 节） | 用户在内地；上架所需的 APP 备案躲不开；香港会多出数据出境手续 |
| 云服务商 | **阿里云**（第二十轮确认） | 服务器、文件存储、CDN、短信、语音识别、内容安全、大模型平台、备案都在一家办 |
| 编程语言 | TypeScript（app、管理端、服务器全部统一） | 一种语言、共享类型和规则代码；Claude 写起来和改起来都最可靠 |
| 学生端 app | React Native + Expo，一套代码出 iOS 和安卓 | 跨平台；生态成熟；能接国内推送等原生能力 |
| 管理端 | React 网页 + Ant Design（中文后台组件库） | 管理员在电脑上用；海外也能通过 CDN 快速打开 |
| 服务器程序 | Node.js（Fastify 框架）+ REST 接口（带版本号） | 手机上会同时存在新旧版本的 app，REST 加版本号最容易保持兼容 |
| 数据库 | PostgreSQL（云数据库 RDS） | 账本、事务、复杂查询都可靠 |
| 队列与缓存 | Redis | 定时事件、AI 处理任务排队、并发锁 |
| 作品文件 | 对象存储 OSS + CDN | 视频、音频、图片；app 直接上传，不经过服务器 |
| AI | 自建"AI 网关"，供应商和模型在后台可切换 | 设计宪法第 19 条：对 AI 没有忠诚 |
| 推送 | iOS 用 APNs；安卓用聚合推送（个推或极光）接各手机厂商通道 | 国内安卓手机没有谷歌推送 |

## 1. 为什么服务器不放香港

香港服务器确实**不需要 ICP 备案**（备案只针对中国内地的服务器）。但对智游记来说，放香港不会更简单，反而更复杂：

1. **上架所需的 APP 备案躲不开。**
   - 苹果中国区和国内安卓商店上架，都要求填写 APP 备案号，这和服务器放在哪里无关。
   - 备案要通过内地服务器的接入商办理。服务器放香港，为了拿备案号，通常还得另外准备一台内地服务器。
2. **会多出数据出境手续。**
   - 对内地法规来说，香港属于"境外"。孩子的数据存到香港，就算"向境外提供个人信息"。
   - 不满 14 周岁未成年人的个人信息属于敏感个人信息，孩子的录音、视频、照片也属于敏感个人信息。
   - 按 2024 年《促进和规范数据跨境流动规定》，敏感个人信息出境，即使不满 1 万人，也要订立标准合同或通过个人信息保护认证。
3. **网络稳定性。**内地访问香港的跨境线路在高峰期可能变慢。周日 20:00 周战争截止前，大家集中上传视频，正好是高峰。
4. **国内服务要在内地才顺手。**短信、语音识别、内容安全、大模型这些国内服务，都在内地调用最快、最稳。

**结论：放中国内地，备案交给云服务商代办。**这是常规流程：在阿里云办备案，需要一台阿里云内地服务器（包年包月 3 个月以上）。ICP 备案和 APP 备案可以一起走。

## 2. 系统组成

```
              学生端 app（iOS / 安卓）            网页管理端（电脑浏览器）
                     │                                   │
                     └──────────── HTTPS ────────────────┘
                                    │
                         ┌──────────▼──────────┐
                         │  API 服务（/v1/...）  │──── PostgreSQL（账本、赛季、作品记录……）
                         └──────────┬──────────┘
                                    │                ┌── Redis（队列、缓存、并发锁）
                         ┌──────────▼──────────┐     │
                         │  后台任务（worker）  │─────┘
                         │  · 赛季时钟与计划事件  │
                         │  · AI 处理流程        │──── AI 网关 → 各家大模型、语音识别
                         │  · 视频与音频处理     │──── 内容安全服务
                         │  · 通知发送          │──── 推送（APNs、个推/极光）、短信
                         └─────────────────────┘
   app 上传作品 ──直传──► OSS（原件 + 转码后的文件）──► CDN ──► app / 管理端播放
```

- **API 服务**：处理所有用户操作（登录、提交、发起进攻、买法宝……），只做"校验 + 写数据库 + 把耗时的事丢给 worker"，保证 app 操作很快有响应。
- **后台任务（worker）**：所有定时的、耗时的、可重试的事情。和 API 是同一份代码，两个启动入口。
- 第一季的规模很小（约 120 名赛季玩家 + 几百名免费用户），API 和 worker 可以先跑在同一台服务器上，以后再拆开。

## 4. 关键技术决定

### 4.1 规则引擎：一套代码跑正式赛季、模拟赛季和测试
- 引擎的形式是：输入"当前状态 + 一个动作或一个时间点"，输出"新状态 + 要记的账"。
- 所有数值都从赛季参数表传进来，代码里不写死任何数字（PRD 第 1 部分约束 1）。
- **对拍：**把我们已有的 Python 模拟器（`智游记S3_赛季模拟器.py`、`法宝模拟.py`）当作"标准答案"。同一串动作分别喂给两边，结果必须一致。这样能保证 app 里的规则和我们模拟验证过的规则是同一套。

### 4.2 时钟和计划事件
- 系统里所有"现在几点"都通过一个时钟服务获取。
  - 正式环境：北京时间的真实时钟。
  - 模拟环境：可以加速的时钟，例如 1 小时跑完 33 天。
- 赛季里的定时事件，例如"D8 中心地开放""周四 20:00 公布配对""某场争夺 72 小时截止"，都存成**计划事件表**（时间 + 类型 + 参数），由 worker 按时执行。
- 每个事件执行**幂等**：同一个事件执行两次，不会重复记账。服务器重启、宕机后补跑，都不会漏，也不会多。

### 4.3 账本
- 粮草、团队分各有一张**只追加**的账本表。每一笔记录都包含：组、数量、来源类型（每日任务、进攻、法宝……）、来源编号、规则版本、时间。
- 余额 = 账本求和（另做缓存加速），每天自动对账一次。
- 出错时不删改原记录，而是记一笔反向冲正。所有人工干预都留操作日志：谁、什么时候、为什么。

### 4.4 并发和"先到先得"
- 先到先得或有截止时间的操作，都在服务器端判定，并用数据库事务加锁：
  - D1 盲拍截止；
  - D8 按排名逆序购买中心地；
  - 仙品竞价和 10 分钟防狙击；
  - 区域争夺的 24 小时同价加入窗口；
  - 认领组长和副组长。
- 一律以**服务器收到请求的时间**为准，不信任手机上的时间。

### 4.5 作品文件
- app 向服务器申请临时上传凭证，然后**直接上传到 OSS**；大视频支持断点续传，网不好也能接着传。
- 上传完成后，worker 依次处理：
  - 转码成统一格式（H.264，最高 720p），方便播放；
  - 抽出音轨，交给语音识别；
  - 抽取关键帧，交给 AI 看画面。
- **原件在孩子账号存续期间完整保留**（数据先存；保留期限的法律要求见 PRD 第 8 部分第 4 节）。
- 文件大小和视频时长的上限在第 5、6 部分定。

### 4.6 AI 网关
- 每个 AI 任务都在后台单独配置"供应商 + 模型 + 提示词版本"。AI 任务包括：
  - 每日任务审核、作品初评、军需任务打分；
  - 知识标签、跨越度判断、知识卡片；
  - 语音转写、看图（截图和视频关键帧）。
- 每次调用都记录：输入、输出、模型、耗时、费用。
- 调用失败时自动重试，必要时切换到备用模型。
- **影子模式**：换模型之前，新旧两个模型同时打分但只采用旧的，对比一段时间、确认新模型更好再切换。
- 详细设计在第 6 部分。

### 4.7 内容安全
- 文字、图片、音频、视频在**公开给观战用户之前**，先调用内容安全服务审核；不通过的进入人工队列。
- 复核员和本组成员在审核完成前就能看到作品，不耽误赛季节奏。

### 4.8 登录与账号
- **学生端**：
  - 家长手机号 + 短信验证码 → 家庭账号 → 多个孩子档案（登录后选"我是谁"）；
  - 登录状态保存在手机的安全存储里，长期有效，不用孩子每次输验证码。
- **管理端**：邮箱 + 密码 + 两步验证。复核员在美国，不用国内短信登录。

### 4.9 推送和消息
- iOS 用苹果推送（APNs）。
- 安卓用聚合推送服务（个推或极光），接入华为、小米、OPPO、vivo、荣耀的厂商通道。
- app 内有**消息中心**兜底：推送没收到，打开 app 也能看到所有通知。

### 4.10 app 更新
- 版本更新走应用商店审核发版。
- Expo 自带的"热更新"服务器在海外，国内访问可能不稳定，v1 先不用。

### 4.11 管理端
- 静态网页放在 OSS + CDN 上，美国也能快速打开。数据接口仍在内地服务器，海外访问延迟稍高，但对管理操作没有影响。
- 管理端所有时间同时显示北京时间和本地时间（PRD 第 1 部分约束 4）。

### 4.12 监控
- 日志进阿里云日志服务。
- 出错自动报警，发到管理员邮箱。
- 关键指标做成看板：每日任务量、AI 失败率、待复核数量、账本对账结果。

## 6. 部署与发布

- **服务器**：代码放 GitHub 私有仓库。每次改动自动跑全部测试，测试通过后构建 Docker 镜像，推送到阿里云容器镜像服务，服务器拉取更新。数据库结构变更前自动备份。
- **app**：用 Expo 的云构建（EAS Build）出安装包，依次经过：
  1. 内测：iOS 用 TestFlight，安卓用内测安装包；
  2. 提交应用商店审核；
  3. 上架。

## 7. 规模与成本（粗估，以成本模型阶段为准）

- **第一季规模**：约 120 名赛季玩家 + 几百名免费用户。
- **压力最大的时刻**：周日 20:00 周战争截止前，以及每场区域争夺截止前，大家集中上传视频。
- **起步配置**：一台云服务器（API + worker）、一个云数据库、一个 Redis、对象存储 + CDN。这个规模下，云资源每月大约几百元。
- **AI 费用**：每日任务审核每次约 0.01 元（个人系统设计第 7.2 节）；作品初评涉及视频转写和看图，单价更高，但第一季只有约 150 件。
- 准确数字在"收费成本模型"那一步按真实报价算。

## 9. 决定与待办

1. **云服务商：阿里云**（第二十轮确认）。
2. **域名**：首选 `zyjedu.com`（用户第二十轮提出）。
   - 从这里查不到域名是否已被注册，买域名时在阿里云直接查。
   - 被注册了的话，备选 `zyjedu.cn`、`zhiyouji.com`、`zhiyouji.cn`。
   - 域名里带"edu"本身没有问题；备案时填写的网站名称是否会被要求做行业前置审批，办备案时核实。
3. **包名（Bundle ID）**：格式 `com.公司英文名或拼音缩写.zhiyouji`。
   - **【待补】用户以后再定公司的英文名或拼音缩写**（第二十轮标记）。
   - 包名必须在 APP 备案之前定下来，到时提醒。
