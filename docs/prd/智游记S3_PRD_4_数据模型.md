# 智游记 S3 · v1 PRD · 第 4 部分：数据模型（当前版本 v0.6）

> 本部分回答：系统里存哪些东西、它们之间是什么关系、哪些规则由数据库来保证。
>
> 读者：主要是 Claude 写代码时用（之后会直接变成数据库结构和迁移脚本）。你只需要看第 0 节的总览和第 11 节"数据先存清单"，检查有没有漏掉要留下来的东西。
>
> 依据：PRD 第 1–3 部分；《个人系统设计》v0.2.2；《试运行内容库》v0.3.1；《法宝设计》v0.3.2。

## 0. 总览

数据分成 9 块：

```
 账号与人 ───────┐
 （家庭、孩子、管理端用户）│
                 ▼
 内容（题库、评分族、分类表）──► 赛季结构（赛季、服、组、组员、地块、阵营）
                                     │
                                     ▼
                        赛季玩法（计划事件、出价、争夺、周战争、军需、
                                  商店、竞价、法宝、大团战）
                                     │
                         ┌───────────┼───────────┐
                         ▼           ▼           ▼
                 作品与评分       账本（粮草、     通知与动态
             （作品、文件、AI 分、   团队分）     （消息、战报、动态）
               人工分、复核分派）
                         ▲
 个人学习（每日任务、知识卡片、问卷、周月报）

 系统：参数版本、AI 调用记录、内容安全、操作日志
```

## 1. 通用约定

| 约定 | 说明 |
|---|---|
| 主键 | 全部用 UUID |
| 时间 | 数据库存 UTC，显示时换算成北京时间（管理端同时显示本地时间）。"赛季第几天"由时间和赛季开营日计算，不单独存 |
| 分和粮草 | 团队分以 **0.01 分**为单位存整数（第二十八轮由 0.1 改为 0.01）；粮草存整数（PRD 第 3 部分第 1 节、20.7） |
| 多服 | 赛季里的对象都带"所属服"，两个服的数据互不干扰 |
| 版本 | 参数、评分族、AI 提示词都有版本号。任何结算、评分记录都存下当时用的版本 |
| 只追加 | 账本、AI 评分、人工评分、操作日志、竞价出价、组长变更，**只增不改不删**；更正用新记录 |
| 删除 | 题库等内容只做"停用"，不真删；孩子注销账号时的处理见第 12 节 |

## 2. 账号与人

| 表 | 关键字段 | 说明 |
|---|---|---|
| 家庭账号 | 手机号（唯一）、监护人同意的时间和协议版本、状态、最后登录时间 | 一个手机号一个家庭账号；最后登录时间用于"连续 2 年不登录"的清理 |

| 复核员请假 | 复核员、开始日期、结束日期 | 请假期间不分派作品 |

## 4. 赛季结构

| 表 | 关键字段 | 说明 |
|---|---|---|
| 赛季 | 名称、状态（草稿 → 报名中 → 已分组 → 进行中 → 大团战 → 待终局结算 → 已结束 → 已归档）、开营日期、当前参数版本 | PRD 第 3 部分第 2 节 |

## 5. 赛季玩法

### 5.2 "提交偏好、统一分配"的轮次

盲拍、D8 中心地、灵品分配、开营凡品，用同一套结构：

| 表 | 关键字段 | 说明 |
|---|---|---|
| 分配轮 | 所属服、类型（第 1 批选地、D8 中心地、灵品、开营凡品）、开始时间、截止时间、状态、处理时间 | |

| 分配结果 | 分配轮、小组、分到的东西、付出的粮草、处理顺位 | 截止时一次性生成 |

### 5.3 区域争夺

| 表 | 关键字段 | 说明 |
|---|---|---|
| 争夺 | 所属服、地块、题目、守方、发起时间、加入截止、提交截止、辩论选持方截止、状态、结果、结算时间、**结算依据（人工 / 超时按 AI / 管理员）** | 状态机见 PRD 第 3 部分 10.7 |

## 6. 作品与评分

| 表 | 关键字段 | 说明 |
|---|---|---|
| 作品 | 类型（区域、周战争、军需个人、军需总结、大团战战线、大团战主战场）、关联对象、所属小组、提交人、第几版、提交时间、是否最终版、文字内容、署名的组员、内容安全状态、公开范围（本组 / 全服）、**知识标签**（学科、子领域、难度级，由 AI 识别） | 截止前每次重新提交都是新的一版，旧版保留。知识标签给署名组员的赛季回顾用（PRD 第 5 部分 4.1） |
| 文件 | 所属作品、类型（视频、音频、图片、PDF）、原件位置、转码后位置、时长、大小、处理状态、转写、关键帧 | 原件在账号存续期间保留（PRD 第 8 部分第 4 节） |
| 语音转写 | 文件、供应商、模型、全文、分段时间 | |
| AI 评分 | 作品、评分任务、评分族版本、AI 调用记录、总分、各维度分、评语、标记（例如"像 AI 代写"）、**是否正式采用** | 只追加；同一件作品可以有多条（重跑、影子模式），只有一条是正式的 |
| 复核分派 | 作品、复核员、分派时间、到期时间、状态（待复核 / 完成 / 超时 / 改派）、是否第二人复核 | 每件作品有明确负责人 |
| 人工评分 | 复核分派、作品、复核员、总分、各维度分、评语、时间 | 只追加 |
| 结算用分 | 作品、最终分、**依据（人工 / 超时按 AI / 管理员改判）**、决定时间、决定人 | 复核员看板的数据来源 |

- **复核员看板**（PRD 第 3 部分 10.5）直接从"复核分派"和"结算用分"统计：每人分到多少、按时完成多少、超时按 AI 分结算多少件（可点开明细）、平均用时、双人复核分差。

## 7. 账本

| 表 | 关键字段 | 说明 |
|---|---|---|
| 粮草账本 | 赛季、服、小组、数量（正负整数）、类型、关联对象、参数版本、说明、时间、记账人（系统或管理员）、冲正了哪一条 | |
| 团队分账本 | 同上，数量以 0.01 分为单位 | |
| 余额缓存 | 小组、粮草、团队分、更新时间 | 每天自动对账：缓存必须等于账本求和 |

- **粮草类型**：开营、每日任务、军需、进攻、加入、盲拍出价、买中心地、商店、竞价成交、退还、冲正、管理员调整。
- **团队分类型**：领地收益、夺地战功、守地战功、周战争、轮空、全员参与奖、大团战战线、夺取产出、主战场、法宝效果、粮草折算、冲正、管理员调整。
- 数据库保证：**粮草余额不能为负**。扣粮草的操作在同一个事务里先检查余额（含冻结），不够就失败。

| 美术资源 | 资源位（赛季地图、某个地块、某件法宝、组徽、头像、土地公、开屏）、图片、作者署名、上传人、启用状态、启用时间 | 管理端可替换，app 里有"插画作者"页（PRD 第 5 部分第 7 节） |
| 赛季回顾 | 孩子、赛季、内容（探索地图、最难的知识、参与的作品、小组名次、数字）、生成时间 | PRD 第 5 部分 4.1 |

## 11. 数据先存清单（请你检查有没有漏）

这些数据**在孩子账号存续期间完整保留**，作为孩子的学习档案，供 v1.1 折算修为和能力、校准 AI、衡量孩子的成长。（第二十六轮修订：原写"永久保留"，但法规要求儿童个人信息的存储不超过实现目的所必需的期限，见 PRD 第 8 部分第 4 节。）

1. **每一次每日任务**：原始证据、讲解原文（录音和转写）、人机协作说明、AI 给的表达档和人机协作档、知识标签、难度级、当天年级、跨越度。
2. **每一件团队作品**：所有版本的原件、转写、署名的组员。
3. **每一次评分**：AI 分（含用的模型和评分族版本）、人工分、结算依据。
4. **账本**：粮草和团队分的每一笔变动，以及当时的参数版本。
5. **注册问卷**：全部答案和 30 秒挑战的录音（成长基线）。
6. **赛季过程**：每一次出价、进攻、加入、法宝使用、组长变更、战线分配。
7. **AI 调用记录**：用于算成本、比较模型。

## 12. 数据保留与删除（细节在第 8 部分核实）

- 孩子注销账号：个人信息（昵称、头像、录音、照片、视频）删除或匿名化；小组的账本和名次保留，但不再显示这个孩子的名字。
- 作品里出现多个孩子时，按"整件作品匿名化"处理，避免影响其他孩子的记录。
- 具体的保留期限和法律要求，在第 8 部分"合规"里核实。

## 13. 已定（第二十三轮）

1. **年级自动升级**：每年 9 月 1 日，系统自动把所有孩子的年级 +1，并提醒家长核对（来源记为"自动升级"）。
2. **超过每日上限的提交**：照样进修行日志、生成知识卡片，只是不产粮草。修行日志就是孩子的日记。"每日任务计数"表里，这类提交记为"不计入粮草"。
