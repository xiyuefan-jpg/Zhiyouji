## 1. 通知

### 1.1 渠道

| 渠道 | 用在哪 |
|---|---|
| 推送 | 孩子手机上的通知：iOS 用苹果推送，安卓用聚合推送接各厂商通道（PRD 第 2 部分 4.9） |
| app 内消息中心 | 所有通知都在这里留一份；推送没收到也不会漏 |
| 短信 | 登录验证码；**第三十轮起也发紧急提醒**（见 1.2 下方说明）；不发营销短信 |
| 管理端通知中心 + 邮件 | 给管理员和复核员 |

### 1.2 通知清单

| 事件 | 通知谁 | 方式 | 时间 |
|---|---|---|---|
| 战报 | 全服 | 推送 + 消息中心 | 一天三个公布时刻（PRD 第 3 部分 1.1） |
| 本组被进攻、有组加入进攻 | 守方全组 | 推送（实时） | 立即，夜间免打扰时段顺延到早上 |
| 本组的作品还没交（截止前 6 小时、2 小时） | 组长、副组长 | 推送 | 定时 |
| 军需任务还没交自己的那份（截止前 3 小时） | 还没交的组员 | 推送 | 定时 |
| 互赠词条、偏好提交、战线分配还没提交 | 组长、副组长 | 推送 | 截止前 3 小时 |
| 仙品出价被超过 | 出价组的组长、副组长 | 推送（实时） | 立即 |
| 每日任务审核结果 | 孩子本人 | 推送 + 结果页 | 出结果时 |
| 法宝被用在本组身上 | 本组 | 实时广播 + 推送 | 立即 |
| 赛季资格开通、分组公布 | 孩子本人 | 推送 + 消息中心 | 发生时 |
| 公告 | 按公告范围 | 推送 + 消息中心 | 选定的公布时刻 |
| 复核分派、快到时限 | 复核员 | 管理端 + 邮件 | 分派时；到期前 6 小时 |
| 复核超时、每日任务异常、内容安全不通过、复核员"转给管理员"、计划事件失败 | 管理员 | 管理端 + 邮件 | 立即 |

**网站版的通知（第三十轮）**：表里的"推送"改为两档：
- 消息中心：所有通知都有；
- 短信（发到家长手机）：只发这几种：
  - 本组被进攻、有组加入进攻：守方全组；
  - 本组作品还没交（截止前 6 小时）：组长、副组长；
  - 军需任务自己那份还没交（截止前 3 小时）：本人；
  - 仙品出价被超过：组长、副组长。
- 战报、审核结果、公告等只进消息中心，不发短信。
- 短信模板要在阿里云短信服务里报备审核（固定文字 + 变量），内容只写"智游记：你们组有新的情况，请打开网站查看"一类的话和链接，不写孩子姓名。

### 1.3 规则
- **短信**（第三十轮）：每个手机号每天最多 5 条；同一个家庭多个孩子的同类提醒合并成一条；夜间免打扰同样适用。
- **夜间免打扰**：北京时间 21:30 到次日 07:00 不给孩子发推送，这段时间的通知顺延到早上（第二十七轮确认）。区域争夺至少有将近 3 天，顺延几个小时不影响迎战。
- **每天上限**：每个孩子每天最多收到约 8 条推送；超过的只进消息中心。
- **合并**：同一个组短时间内的多条同类通知合并成一条，例如"有 2 个组加入了对你们的进攻"。
- **分类**：按国内手机厂商推送通道的要求，把通知标成"个人或小组相关"或"运营"类，前者不受运营类配额限制，例如被进攻、审核结果。具体分类按各厂商规则配置。

## 2. 合规

### 2.1 未成年人个人信息（必须做）

智游记的用户大多不满 14 周岁。相关法规的主要要求，以及我们的做法：

| 要求 | 我们的做法 |
|---|---|
| 不满 14 周岁未成年人的个人信息属于敏感个人信息，处理时要有特定的目的和充分的必要性，并取得监护人同意 | 见下方"监护人同意" |
| 制定专门的儿童个人信息保护规则和用户协议，并指定专人负责 | 准备《用户协议》《隐私政策》《儿童个人信息保护规则》三份文件；**儿童个人信息保护负责人由用户本人担任**（第二十七轮确认），姓名和联系方式写进《儿童个人信息保护规则》 |
| 征得同意时要同时提供拒绝选项，并明确告知目的、方式、范围、存储地点和期限、安全措施、拒绝的后果、投诉渠道、更正和删除的方法 | 三份文件写全这些内容；同意页面有"同意"和"不同意"两个按钮 |
| 不收集和服务无关的信息（最小必要） | 只收手机号、昵称、年级、问卷和学习提交；不收姓名、学校、身份证号、位置 |
| 存储不超过实现目的所必需的期限 | 见第 4 节，原来"永久保留"的写法已经改掉 |
| 加密存储 | 数据库和文件存储都开启加密（第 3.2 节） |
| 工作人员按最小授权访问，访问要经过负责人或其授权的管理人员审批，并记录 | 复核员只能看分派给自己的作品（分派就是授权），盲审；所有查看都记日志（第 3.1 节） |
| 委托第三方处理（云服务、AI、推送、短信）要做安全评估并签委托协议 | 只选国内正规服务商；逐家确认数据处理条款（不用于训练、保存期限）；在隐私政策里列出第三方清单 |
| 每年做一次未成年人个人信息保护合规审计，并报告网信部门 | 每年自行或委托专业机构审计并报送；第一次在上线后的第一个报送周期内完成 |

**监护人同意要"真的同意"，但可以很轻**（第二十六轮修订内容库 10.0）：
- 用户原来的想法是"名义上的提示、免责"。但法规要求的是监护人的同意，而且要有拒绝选项，所以只让孩子勾一个"监护人已知道"不够。
- 好在登录本来就用**家长的手机号**收验证码。做法如下（第二十七轮确认）：
  1. 第一次登录时，输完验证码，显示一屏"家长确认"：用几行字说清楚收集什么、用来做什么、存多久、怎么删除；**作品结算后其他用户（包括观战的免费用户）可以看到，作品不显示真实姓名**；附三份文件的链接；
  2. 两个按钮："同意" / "不同意"；不同意就无法使用，并说明原因；
  3. 同一屏写一句：作品会由评审人员在线查看和打分，评审人员中有在境外的中国籍大学生（第二十八轮：不单独设同意项，不写姓名；三份文件里写同样的内容）；
  4. 记录同意的手机号、时间、文件版本；文件有实质变化时，下次登录重新确认。
- 这一步由家长在自己手机上完成，**不需要问卷，也不需要家长另外填任何东西**。
- 同意记在家庭账号上，对这个手机号下的所有孩子档案生效。

### 2.2 数据出境：你和复核员在美国（第二十八轮）

**事实**
- 数据存在国内，但只要境外的人可以查询、调取、下载、导出，就算"数据出境"。你和复核员在美国查看孩子的作品、录音、修行日志都属于这种情况；你在国内时查看不算出境。
- 不满 14 周岁未成年人的个人信息由法律直接列为敏感个人信息，和用途无关。
- 2024 年《促进和规范数据跨境流动规定》：不满 1 万人的敏感个人信息出境，要订立标准合同或通过认证（第八条）；即使免办这些手续，也要告知、取得个人单独同意、做个人信息保护影响评估（第十条）。《个人信息保护法》第三十九条要求告知境外接收方的姓名或名称、联系方式等。

**用户的决定（第二十七、二十八轮）**
- 第一季先运营，同时办方案 A（影响评估 + 标准合同 + 备案）。
- 境外的管理员和复核员与境内一样：能看到孩子的身份信息，能下载作品。
- 不设单独同意项。境外评审写进三份文件，并在家长确认页上提一句（2.1 第 3 步）：评审人员中有在境外的中国籍大学生。不写具体姓名。
- 用户明确表示自己承担这部分法律风险，不需要 Claude 再提醒。

**留档，供律师参考**
- 现在的做法和法规要求的差距：没有告知境外接收方的姓名和联系方式；没有取得单独同意；标准合同和备案还在办。
- v0.2 提出的四项系统措施（账号所在地、境外去身份、"仅境内"标记、境外查看计数）已取消。
- 保留：所有管理端账号查看孩子数据都记日志（第 3.1 节）。这是儿童个人信息规定本身对工作人员访问的要求，和出境无关。

### 2.3 备案、资质与上架

| 事项 | 状态 / 做法 |
|---|---|
| ICP 备案、APP 备案 | 必须；通过阿里云办理（PRD 第 2 部分第 8 节） |
| 软件著作权 | 安卓商店通常要求；代码第一版出来后申请 |
| 游戏版号 | 上架分类选"教育"，商店描述不用"游戏"；app 内不收费、不卖道具（PRD 第 5 部分第 6 节）。**是否仍有被认定为游戏的风险，请律师或应用商店客服确认** |
| 生成式 AI 登记 | 调用已备案大模型 API 的应用或功能，由地方网信办登记，并要公示模型名称和编号。我们只用 AI 打分、生成反馈和知识卡片，**是否需要登记，向属地网信办或阿里云咨询**；无论如何，app 里都保留公示页（PRD 第 5 部分第 8 节） |
| 网络安全等级保护 | 建议评估是否需要做二级备案（处理大量未成年人信息的系统通常建议做） |
| 支付 | app 内无支付，不出现价格和报名方式（PRD 第 5 部分 6.2） |

### 2.4 应用商店的隐私审核（常见要求）

国内应用商店和工信部的检测，通常会检查以下几点，开发时必须做到：

- 第一次打开时，先弹出隐私政策并取得同意，**同意之前不收集任何信息、不调用任何第三方 SDK**；
- 不在启动时一次性索要权限；用到相机、麦克风、相册时再请求，并说明用途；
- app 内能找到隐私政策、第三方 SDK 清单、个人信息收集清单；
- app 内能**注销账号**；
- 拒绝非必要的权限后，app 的基本功能仍能使用。

### 2.5 内容安全（孩子上传的内容）
- 作品公开给观战用户之前，必须通过内容安全审核（PRD 第 6 部分第 7 节）。
- app 内提供举报入口；管理员处理举报。
- 处理记录保留，用于应对检查。

## 3. 安全

### 3.1 账号与访问
- 学生端：家长手机号 + 短信验证码；验证码限制频率，失败多次要做图形验证。
- 管理端：邮箱 + 密码 + 两步验证；按角色授权（PRD 第 7 部分第 0 节）。
- **复核员只能打开分派给自己的作品**；管理员查看具体的孩子数据时也记日志（谁、什么时候、看了什么）。
- 管理端长时间不操作自动退出。

### 3.2 数据
- 所有通信走 HTTPS。
- 数据库、文件存储开启加密。
- 文件存储不公开：作品和录音用有时效的临时链接访问。
- 每天自动备份，可以恢复到任意时间点；每季度至少演练一次恢复。

### 3.3 应用
- 接口限制访问频率，防止刷接口。
- 所有输入都校验；孩子提交的内容交给 AI 时，按"数据"处理，防止里面夹带的指令影响打分（PRD 第 6 部分第 3 节）。
- 依赖的第三方代码库定期扫描漏洞。
- 上线前做一次基础的安全测试。

### 3.4 公平与防作弊
- 所有截止、先到先得、竞价，一律以服务器时间为准（PRD 第 2 部分 4.4）。
- 粮草和团队分只能由系统按规则记账；人工调整必须写原因并留日志。
- 异常行为提醒管理员，例如同一个家庭账号下的孩子在不同组、同时操作同一场争夺。

### 3.5 出事怎么办
- 发生数据泄露时：立即止损；按法规通知受影响的孩子的监护人，并向有关部门报告；事后复盘。
- 事先写好处置手册（谁负责、按什么步骤、怎么通知），上线前演练一次。

## 4. 数据保留与删除（第二十六轮修订）

法规要求儿童个人信息的存储不超过实现目的所必需的期限。原来"永久保留"的写法改为：

| 数据 | 保留多久 | 之后怎么办 |
|---|---|---|
| 孩子的学习档案（每日任务、知识卡片、作品、评分、问卷、录音） | **孩子账号存续期间**完整保留：这就是孩子的学习档案，也是 v1.1 折算修为的依据 | 注销后删除；只保留不能识别到个人的统计数据 |
| 账本、名次 | 和赛季记录一起保留 | 孩子注销后，记录里不再显示这个孩子 |
| 长期不登录的账号 | 连续 2 年不登录（第二十七轮确认） | 提前 30 天短信通知家长；家长登录一次即可保留；不回应的删除 |
| 登录、操作日志 | 按法规要求的最短期限保留（例如网络日志不少于 6 个月），之后删除 | — |
| 用于校准 AI 的数据 | 只用匿名化处理后的数据 | — |

- 家长可以在 app 里申请导出或删除孩子的数据（PRD 第 5 部分 G4）。
- 一件作品里有多个孩子时，其中一人注销，整件作品做匿名化处理（PRD 第 4 部分第 12 节）。

## 5. 上线前需要律师确认的事项

1. 数据出境（2.2）：方案 A 的手续（影响评估、和每位境外接收方订立标准合同、备案）的时限和材料；"履行合同所必需"的豁免能否适用；2.2"留档"里列出的差距怎么补。
2. 三份文件的定稿：《用户协议》《隐私政策》《儿童个人信息保护规则》。Claude 可以先起草，律师审核。
3. 游戏版号：以教育类上架是否有被认定为游戏的风险（2.3）。
4. 生成式 AI 是否需要登记（2.3）。
5. 每年的未成年人个人信息保护合规审计怎么做（2.1）。
6. 是否需要做网络安全等级保护备案（2.3）。

4. 北京时间 21:30 到早上 07:00 不给孩子发推送，通知顺延到早上。
