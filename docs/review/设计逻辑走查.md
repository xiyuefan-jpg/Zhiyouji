# 设计逻辑走查（2026-11-14）

> 方法：用演示模式（`npm run demo -w @zhiyouji/server`，模拟时钟 + 31 个机器人孩子）把网站和管理端真正跑起来，在手机尺寸的浏览器里扮演家长、孩子、组长、守方、管理员、复核员，从注册一路走到第一场争夺结算。每一步对照《项目说明与决策日志》第 2 节"设计宪法"和 PRD 第 3、5、7 部分，看交互是不是在印证设计逻辑。
>
> 走到的环节：隐私弹窗 → 家长登录 → 家长确认 → 建两个孩子档案 → 新手引导 → 土地公问卷（含 30 秒录音）→ 每日任务（证据图 + 按住说话 + AI 说明）→ 审核结果和知识卡片 → 周小结 / 月报告 → 管理员开通资格 → 自动分组 → 锁定 → D0 分组公布 → 认领组长 → 盲拍 → 开营法宝 → 地图和地块 → 发起进攻（报价）→ 守方收到通知和短信 → 管理员收到"兄弟姐妹在对面"提醒 → 争夺详情（题目）→ 作品工坊（素材箱、组装、署名）→ 复核员盲评 → 结算 → 战报、排名、分数和评语 → 法宝囊、周战争、军需任务。
>
> 没有手动走到的：用法宝、周战争和军需的提交、商店和仙品竞价、大团战、终局和奖学金、赛季回顾。这些由自动测试（`apps/server/test/fullSeason.test.ts` 连跑三季）覆盖，下次走查补手动。

## 一、印证了设计逻辑的地方

| 设计宪法 | 在哪里看到 |
|---|---|
| 1 输入→输出闭环 | 每日任务的讲解必须有"① 自己想到的例子 ② 原来哪里不懂、现在怎么懂了"；军需任务"每人用一句话把一个知识讲给组员听"；争夺题目写明"讲给：一个没学过这个知识的初中生或普通成年人" |
| 2 防 outsourcing | 每日任务交"和 AI 对话的截图"做证据，讲解默认"按住说话"，再说一句"你是怎么用 AI 的"；不交证据交不上去 |
| 3 PvP 是动机核心 | 进攻前报价"基础 40 → 40 粮草，之后剩 20"；守方消息写"交作品就是迎战，不花粮草"；被进攻立刻首页红色提醒 + 家长手机短信；领地每天产出团队分 |
| 4 能不人工就不人工 | 分组自动（按年级蛇形，各组平均年级 4.5–4.8，兄弟姐妹自动分开）；没人认领时系统指定组长；提醒、战报、结算全自动；AI 初评 + 人工复核 |
| 8 团队自主 | 组长先到先得自己认领；每个组员都能往素材箱放东西，组长或副组长组装提交 |
| 9 修漏洞，不禁外交 | 同一家庭的孩子在一场争夺的两边时，管理员看板提示"请留意是否有串通"，只提醒、不拦 |
| 10 奖励只挂在可验证的数据上 | 每日任务的粮草只来自 AI 审核通过；免费用户的每日任务只进修行日志，不给粮草 |
| 20 反馈以教育为先 | 每日任务反馈分"做得好的 / 可以更好的"；争夺结果里孩子看到每个维度的得分和复核员的评语（哪里好、哪里扣分、下次怎么改） |
| 其他 | 隐私弹窗同意前不发任何请求；家长确认写明"评审人员中有在境外的中国籍大学生"；短信不写孩子名字、晚上不发、同一家合并 |

## 二、发现的问题和处理

### 和设计逻辑直接相关（已修）

1. **孩子看不到"怎么评分"。** 争夺页只有题目和受众，没有这块地的学科和题型、评分维度、50 / 75 分的标准、作品要求、"小队友可以做什么"。不知道怎么评，就没法有针对性地"讲明白"。
   → 争夺页和作品工坊都加了"怎么评分"：学科 · 题型、讲给谁、作品要求、每个维度看什么、50 分和 75 分的样子、小队友可以做什么（内容库第 2–3 节、第 4 节）。
2. **作品工坊没有"人机协作说明"。** 内容库第 2 节规定每件团队作品都要附，每个评分族里占 10 分；服务器支持，网站没有填的地方。
   → 加上了，提示"评分里占 10 分"。
3. **作品形式默认是"文字"。** 内容库规定主体三选一（视频、音频、图文），纯文字最难"讲明白"、也最容易被 AI 代写（宪法第 2 条）。
   → 默认改成视频，顺序改为视频 / 音频 / 图文 / 只有文字；选"只有文字"时提示它最容易被 AI 代写。（辩论立论允许 ≤800 字图文，所以没有删掉文字选项。）
4. **复核员看不到题目和受众。** 复核页只有作品和评分表，"准确""教会受众"两项（共 55 分）没法判断。
   → 复核页加了题目、学科 · 题型、受众，评分表加了"看什么"一列和 50 / 75 分标准。
5. **AI 初评也拿不到题目。** 服务器给 AI 的请求里只有题目编号，没有题目原文和受众；接上真的大模型以后同样判断不了"教会受众"。
   → 请求里加了 `task`（题目、受众、学科、题型），AI 调用记录里也记题目。
6. **盲拍的代价和取舍看不到。** 页面没说出价一定会扣（每组都会分到一块地），确认框反而写"拍到了才扣"；也没说"出价低的组在开营法宝里先挑"。设计里"多花粮草抢好地，还是省粮草先挑法宝"的取舍（宪法第 15 条：用代价引导）孩子看不到。每块地也只有名字，看不到学科、是不是辩论地。
   → 盲拍页写清规则；每块地显示学科和题型；确认框改成"这 X 粮草一定会扣掉"。开营法宝、中心地、灵品也同样显示规则和每件法宝的效果。
7. **盲拍结果不公开。** PRD 第 3 部分 8.6 要求"结果立即全服公布，包括每组的出价"，战报里只有"结果公布了"一句。
   → 盲拍页截止后列出每组的出价和拿到的地；战报和广播写成"某组出价 X，拿到某地；……"。中心地逆序购买的战报也写明谁花多少买了哪块。
8. **小组页没有本组微信群二维码。** PRD E1、第二十九轮要求；接口有，页面没接。
   → 加上了；还没上传时写"老师还没上传本组的微信群二维码"。

### 体验和稳健性（已修）

9. **倒计时、问候用的是手机自己的时钟。** 孩子手机时间不准时，"还剩多久""早上好"都会错。→ 服务器每个响应带上自己的时间，网站按服务器时间算。
10. **并列时排名每看一次都会变。** 大家都是 0 分时，刷新一下名次就从第 4 变成第 7。规则是"并列时随机"，没有变，只是同一天里随机结果固定下来，不再每次重抽。（引擎测试和 Python 对拍都通过。）
11. **地块页**：没有学科（加了）；法宝效果显示英文代码（改成法宝名）；进攻方自己还看到"加入进攻"按钮（去掉）；加了"从几号起归某组"；确认框的截止时间写成实际日期。
12. **选图片的按钮是浏览器自带的英文"Choose Files"，选完看不到缩略图。** → 换成中文按钮"＋ 选图片或拍照"，显示缩略图，可以去掉；素材箱里的文件写明是谁放的、是图片还是视频。
13. **管理端**：搜索孩子开通资格时，看不出谁已经开通（加了"已开通"标签）；报名名单的状态显示英文 `enrolled`（改成中文）。

### 还没处理（记下来）

14. "看看怎么玩"的新手引导看过后记在设备上，换手机或换浏览器会再出现一次。改成记在孩子账号上更好（小事）。
15. 首页几个入口（土、修、日、观）用的是朱红色印章，和"朱红只用在主要按钮和紧急提醒上"有点冲突（视觉小事，等插画到了一起调）。
16. 盲拍、开营法宝的"偏好排序"是点选 + 上下箭头，低年级孩子操作有点多；等真机试用后再看要不要改成拖动。

## 三、演示模式

- 起法：`npm run demo -w @zhiyouji/server`，再起 `apps/web`（:5173）和 `apps/admin`（:5174）。
- 模拟时钟从开营前 13 天开始，只在调用 `POST /v1/dev/advance`（例如 `{"beijing": "2027-02-07 19:05"}`）时往前走；31 个机器人孩子已开通，机器人会替没有真人的组出价、进攻、交作品、做每日任务。
- 管理员 `boss@demo.cn`、复核员 `rev@demo.cn`，密码 `demo-password-1`，两步验证码用 `GET /v1/dev/totp?email=…` 取（模拟时间下的验证码）；家长登录验证码用 `GET /v1/dev/code?phone=…`，或者直接打开 `/v1/dev/login?phone=…` 免验证码登录。
- 只用于本地试用，`main.ts` 不加载这些。
