# 智游记 · 数据泄露处置手册（草稿）

> 依据：PRD 第 8 部分 3.5（"事先写好处置手册，上线前演练一次"）、2.1、第 4 节。
>
> **这不是法律意见。**向监护人和主管部门通知、报告的时限和方式，上线前请律师按最新法规确认（PRD 第 8 部分第 5 节）。标【待填】的地方要补。

## 0. 一页结论

1. **先止损，再查清，再通知**；每一步都记下时间和做了什么（写进本手册末尾的处置记录）。
2. 负责人：儿童个人信息保护负责人（用户本人，PRD 第 8 部分 2.1）。联系方式【待填】。
3. 能用系统做的止损都有现成的办法（第 2 节）：停用账号、让所有人重新登录、暂停赛季、换密钥。
4. 查范围靠两本日志：**查看记录**（谁看了哪个孩子的什么）和**操作日志**（谁改了什么），都在管理端能查。
5. 涉及孩子个人信息的，按法规告知受影响孩子的监护人，并向有关部门报告（第 4 节）。

## 1. 什么算"出事"

| 级别 | 例子 | 怎么办 |
|---|---|---|
| 严重 | 数据库、文件存储或备份被别人拿到；管理员账号被盗用；大批孩子的信息（家长手机号、作品、录音、修行日志）被不该看的人看到或下载 | 全部步骤，立即 |
| 一般 | 一个复核员账号的密码泄露但没有异常查看记录；某个接口能看到不该看的内容但还没被利用 | 止损 + 查清 + 修复；查清后确认没有泄露的，记录在案即可 |
| 观察 | 可疑的登录失败、接口被刷（429 很多） | 记录，观察几天 |

发现的渠道：家长、孩子、复核员反馈；管理端通知（计划事件失败、异常提醒）；阿里云的安全告警；自己巡检日志。

## 2. 止损（发现后 1 小时内）

按情况选做，做完一项记一项：

| 情况 | 做法 |
|---|---|
| 某个管理员或复核员账号被盗 | 管理端"管理端账号"里**停用**它（立即下线，`POST /v1/admin/users/:id/disable`）；查它的查看记录（第 3 节） |
| 不确定哪个账号出了问题 | 在服务器上让一边或两边**所有人重新登录**：`npm run revoke-sessions -w @zhiyouji/server -- admin "原因"`（`family` / `all` 同理）；会写进操作日志 |
| `SERVER_SECRET` 泄露（它签登录、上传凭证和下载链接） | 换一个新的长随机串，重启服务器，再 `revoke-sessions all`；之前发出的上传、下载链接全部失效 |
| 数据库密码、阿里云 AccessKey 泄露 | 在阿里云控制台改密码 / 禁用旧的 AccessKey、建新的，更新服务器的 `.env` 后重启 |
| 赛季在进行中，需要停一下 | 管理端"赛季监控与干预"里**暂停**这个服（计划事件之后顺延，PRD 第 3 部分第 16 节） |
| 某个接口有漏洞 | 先在 nginx 里把这个路径挡掉（返回 503），修好、测试通过后再放开 |
| 文件存储的链接被转发出去 | 下载链接本来就有时效；换 `SERVER_SECRET`（以后是 OSS 的签名密钥）让所有旧链接失效 |

**不要**删除日志或数据库记录来"清理现场"：账本和日志只追加，查清范围要靠它们。

## 3. 查清范围（24 小时内初步结论）

1. **查看记录**（管理端"查看记录"，或 `GET /v1/admin/view-log?adminUserId=…&from=…&to=…`）：可疑账号在可疑时间里看了哪些孩子、什么内容（作品、每日任务、报名名单含家长手机号、找孩子、赛季回顾、家长申请）、是查看还是下载。
2. **操作日志**（管理端"操作日志"，`GET /v1/admin/op-log`）：可疑账号改了什么（参数、账本、地块、组长、公告……）。每个管理端接口留什么痕，见 `apps/server/src/http/audit.ts`。
3. **服务器访问日志**（nginx）：来源 IP、时间、路径。
4. **阿里云**：RDS 的 SQL 审计、OSS 的访问日志、AccessKey 的调用记录（ActionTrail）。
5. 列出受影响的孩子：孩子编号 → 家庭账号 → 家长手机号（只在处置时导出，处置完删除导出的文件）。
6. 判断：泄露了哪些信息（手机号？作品？录音？）、多少人、有没有被扩散。

日志保留期限：操作日志、查看记录 400 天；登录记录、短信记录 183 天（PRD 第 8 部分第 4 节，`DEFAULT_RETENTION`）。**出事后先把相关时间段的日志导出留存**，以免到期被自动清理。

## 4. 通知和报告

> 时限和方式以律师意见为准。下面是要准备的东西。

- **受影响孩子的监护人**：短信（只写"智游记有一件和您孩子账号有关的安全事件，请打开网站查看"一类的话，不写细节，要先在阿里云报备模板【待填】）+ 站内公告（范围：受影响的家庭）。公告里写清：发生了什么、涉及哪些信息、我们做了什么、家长可以做什么（例如留意冒充电话）、联系方式。
- **有关部门**：按法规向属地网信部门等报告【待填：报告对象、渠道、时限，律师确认】。
- **合作方**：告知合作公司【待填】。
- 对外说法统一由负责人发出；复核员、助教不单独回应。

## 5. 恢复和复盘（一周内）

1. 修复漏洞，补自动测试（安全测试在 `apps/server/test/security.test.ts`），全部测试通过后上线；
2. 解除 nginx 的临时封禁、恢复暂停的服；
3. 需要时从备份恢复数据（`docs/deploy.md` 第 5 节的恢复演练步骤）；
4. 写复盘：时间线、原因、影响、做了什么、以后怎么防；结论同步进 `PROGRESS.md` 的"已知问题"和决策日志；
5. 三份文件、处置手册要改的地方一起改。

## 6. 演练（上线前一次，以后每年一次）

用预发布环境（`deploy/docker-compose.yml`）：

1. 假设一个复核员账号被盗：用它登录、打开几件作品；
2. 按第 2 节停用它，确认它马上被踢下线；
3. 按第 3 节在查看记录里找到它看过的作品和孩子，导出受影响名单；
4. 跑一次 `revoke-sessions all`，确认所有人都要重新登录；
5. 起草一份给家长的公告（不发出）；
6. 记录用时，改进本手册。
