## 0. 分期上线（第十三轮决定）

### 0.1 为什么分期
- **符合 MVP 策略：**先把已经验证过的赛季玩法完全自动化，这是试运行赛季最重要的事。
- **控制风险和人工：**主线任务和升阶答辩都需要调试评分细则和 AI 追问，人工复核量也最大。等赛季跑顺了再上，不会两头出问题。
- **用真数据定数值：**升阶门槛、经验曲线现在只能拍脑袋。用试运行赛季的真实每日任务数据来定，准确得多。

### 0.2 三个阶段

| 模块 | **试运行赛季（v1）** | v1.1（试运行后） | v2 |
|---|---|---|---|
| 赛季玩法（区域、战争、大团战、法宝、奖学金） | ✅ | ✅ | ✅ |
| 注册问卷（基线测量 + 兴趣推荐） | ✅ **必须第一天就有** | ✅ | ✅ |
| 每日任务（6 个模板，讲解可用语音或文字） | ✅ 产粮草（赛季玩家），同时**记录**能力档位和知识标签 | ✅ | ✅ |
| 赛季团队作品的个人经验 | ✅ 只记录 | ✅ | ✅ |
| 个人页面 | ✅ 修行日志 + 周/月报告 + "修行境界系统 · 建设中"入口（不显示修为和能力分数） | ✅ 揭晓修为、能力、境界 | ✅ |
| 观战模式（免费用户可看赛季和作品） | ✅（第十六轮确认） | ✅ | ✅ |
| 主线任务 | ❌ | ✅ | ✅ |
| 境界与升阶（含答辩） | ❌ | ✅ | ✅ |
| 加速器 / 定身符 | ❌ | ✅ | ✅ |
| 兴趣 track 任务包 | ❌ | 可选 | ✅ |
| 知识星图可视化 | ❌（标签照样打） | ❌ | ✅ |
| 灵石、挂机、市场、赛季前携带法宝 | ❌ | ❌ | ✅ |

### 0.3 关键做法："数据先存，公式后定"
- 试运行赛季里，**每一次提交都完整保存**：原始作品、语音转写、AI 给的各能力档位、知识标签、所属任务模板、时间。
- 新版本上线时，用**最终确定的公式**把这些记录重新算一遍，折算成 BD 和经验。这样试运行期间公式怎么改都不会影响公平，也不需要"换算比例"。
- **注册问卷必须在试运行第一天就做。**它是基线测量，事后没法补；以后衡量孩子成长、衡量项目成果，都要以它为起点。

### 0.4 试运行期间孩子能看到什么（第十四轮决定：方案二）
- **不显示修为值、能力档位和境界。**新版本上线时一次性揭晓，作为惊喜。
- 只放一个**"修行境界系统 · 建设中"**的入口，写明"你从今天起的每一次修行都会被记录，系统开放时全部计入"，制造期待。
- 显示**修行日志**（见 0.6）：孩子能看到自己学过什么，但看不到分数。

### 0.5 灰度测试
- 第十四轮决定：试运行赛季**不做**主线任务的灰度测试。

### 0.6 修行日志（第十四轮新增，试运行就上线）
**目的：**免费用户（只注册、不报名赛季）没有赛季玩法，在主线和升阶上线之前，需要一个"每天来做每日任务"的理由。修行日志让他们长期看见"自己学了什么"，这本身就是留存的动力。赛季玩家同样可以使用。

**每条记录包含：**
- 日期、模板类型；
- 知识卡片：今天学了什么（AI 根据孩子的提交，提炼成一句话标题 + 两三句摘要）；
- 领域标签（学科 → 子领域），即知识星图的数据，只是先用列表展示；
- 孩子自己的讲解（语音或文字原文）；
- 证据（截图或照片）。

**页面形态：**
- **日历视图**：每天做没做一目了然（只是展示，不带倍率，也不惩罚断签）；
- **领域视图**：按学科分类，显示每个领域学了多少条，点进去能看到每张知识卡片；
- **搜索**：能找到"我以前学过的关于火山的东西"。

**定期回顾（自动生成，很便宜）：**
- **每周小结**：本周学了几个新知识、涉及哪几个领域、哪一条讲得最好；
- **月度修行报告**：本月学习地图、最常探索的领域、"你也许会喜欢"的方向推荐（为以后的兴趣 track 铺路）。这份报告也是一个天然的**转化工具**：可以顺带介绍正在进行的赛季。

**和 BD 的关系：**修行日志里的每一条都是完整保存的原始记录，新版本上线时直接用来折算 BD 和知识星图。修行日志可以看作知识星图的列表版，星图上线后两者并存。

### 0.7 免费用户与赛季玩家（第十四轮新增，第十六轮确认）

| 功能 | 免费用户 | 赛季玩家（付费报名） |
|---|---|---|
| 注册问卷 | ✅ | ✅ |
| 每日任务 + 修行日志 + 周/月报告 | ✅ | ✅ |
| 每日任务产粮草 | ❌（不在赛季里） | ✅ |
| 观战：查看赛季地图、区域归属、排行榜、法宝广播、结算后的作品 | ✅ | ✅ |
| 参与赛季玩法、奖学金 | ❌ | ✅ |
| 修行记录在新版本上线时折算 BD | ✅ | ✅ |

- **观战模式**（第十六轮确认）：免费用户能看到赛季地图上的攻防、法宝广播和结算后的作品，但不能参与。看着别人抢地、开宝箱、拍仙品，再看看他们交了什么作品，是最直接的"下个赛季我也要报名"的理由。
- 因为作品对观战用户公开，报名赛季的同意书里要写明"作品在 app 内公开"（见《试运行内容库》10.2）。

## 1. 个人系统要回答的四件事

| 问题 | 回答 |
|---|---|
| 记录什么成长 | BD 三维：**知识**（学了什么）、**能力**（会做什么）、**兴趣**（想往哪钻） |
| 成长从哪来 | 只来自**产出证据**：每日任务、主线任务、赛季团队作品（少量） |
| 成长换来什么 | 升阶（境界）→ 解锁更多内容和权限；灵石 → 市场（第⑤步设计） |
| 怎么证明是真的 | 产出里必须有本人的讲解（语音或文字，带个人例子）；升阶要答辩 |

```
每日任务（模板，AI 审）   ─→ 粮草（赛季内）+ 灵石 + 点亮知识星图 + 少量能力经验
主线任务（作品，AI+人工） ─→ 大量能力经验 + 灵石 + 作品进入个人档案
赛季团队作品（参与者）    ─→ 少量能力经验
              │
              ▼
BD = ① 知识：领域 × 难度（知识星图，MVP 第二版可视化）
     ② 能力：表达 / 创造 / 思辨 / 人机协作（雷达图）
     ③ 兴趣：自选 1–3 条 track（随境界开放更多栏位）
              │
              ▼
升阶考核（经验门槛 + 作品集 + 答辩）→ 境界提升 → 解锁
```

## 2. 三个维度

### 2.1 知识维度（学了什么）
- 每条每日任务提交后，AI 从**固定分类表**里给它打两个标签：**领域**（学科 → 子领域）和**难度级**。
- **难度标在知识上，不锁在孩子身上。**一年级的孩子学了一个初中概念，就点亮一颗高难度的星。
- 用途：让孩子看见"我学的东西属于哪个领域、哪里学得最多"，从而发现兴趣（用户的原始意图）。
- 试运行赛季就要开始打标签（需要一份初版分类表），可视化放到 v2。

### 2.2 能力维度（会做什么）——四项

| 能力 | 含义 | 在哪些任务里体现 |
|---|---|---|
| **表达** | 能把一个东西讲明白、讲给别人听懂 | 每日任务的讲解、知识教学、区域争夺的现象解释 |
| **创造** | 能做出一个有用的东西 | 劳动创造、兴趣作品、周战争的系统设计 |
| **思辨** | 能提出观点、找证据、反驳和被反驳 | 思辨写作、辩论（朱紫国 / 车迟国类）、大团战的问题分析 |
| **人机协作** | 会用 AI，而且知道 AI 做了什么、自己做了什么、什么时候不该信 AI | 每个任务都附带的"人机协作说明" |

- **为什么不单列"协作"：**团队协作发生在小组里，系统没法验证每个人到底出了多少力（设计宪法第 10 条）。团队协作的回报由赛季团队分承担，不进个人能力。
- **人机协作的评分标准直接沿用 S1/S2 住校生替代方案的四个问题：**
  1. 用 AI 完成了什么；
  2. AI 帮你做了哪些思维工作，你自己想了什么；
  3. AI 的答案和你的想法不一致时，你怎么处理；
  4. 下次你会怎样改进人机协作。

### 2.3 兴趣维度（想往哪钻）
- 注册问卷推荐 2–3 条兴趣 track（例如编程、绘画、篮球、天文），孩子可以自己改。
- 每条 track 对应一组任务（task bundle）。完成后，经验计入对应的能力维度，同时累积这条 track 的熟练度。
- 第一境开放 1 个栏位，之后随境界提升增加，最多 3 个。

## 3. 能力怎么测、怎么给经验

### 3.1 原则
- 每个任务模板都带一张**能力权重表**和一份**评分细则**（rubric）。
- AI 按细则给每项能力打 0–4 档，人工只抽查。
- 经验 = 任务基础经验 × 能力权重 × 质量系数。

### 3.2 公式（初稿，试运行后用真实数据定稿）

```
某项能力获得的经验 = 任务基础经验 × 该能力权重 × 质量系数(该能力档位)

质量系数：0 档 = 0（不合格，不给）  1 档 = 0.5  2 档 = 0.8  3 档 = 1.0  4 档 = 1.3
```

### 3.3 任务模板与权重（初稿）

| 任务 | 基础经验 | 表达 | 创造 | 思辨 | 人机协作 | 知识星图 |
|---|---|---|---|---|---|---|
| 每日任务（任一模板） | 10 | 0.5 | — | — | 0.5 | 点亮 1 颗星 |
| 主线 · 知识教学 | 100 | 0.6 | 0.2 | — | 0.2 | 点亮 |
| 主线 · 劳动创造 | 100 | 0.2 | 0.6 | — | 0.2 | 点亮 |
| 主线 · 思辨（写作 / 辩论稿 / 评论） | 100 | 0.3 | — | 0.5 | 0.2 | 点亮 |
| 主线 · 探究（小课题 / 小实验） | 100 | 0.2 | 0.2 | 0.4 | 0.2 | 点亮 |
| 主线 · 人机协作项目 | 100 | 0.1 | 0.3 | 0.2 | 0.4 | 点亮 |
| 赛季团队作品（每个参与成员） | 15 | 按作品类型 | | | | — |

- **赛季团队作品（用户选 B）：**本周达到粮草参与门槛的成员（可验证数据），每份团队作品各得少量经验，按作品类型分配到能力上。例如辩论记入思辨，系统设计记入创造和思辨。团队赢了 ×1.5，输了 ×1。

## 4. 每日任务

- **交什么：**
  - 学习证据（截图或照片）；
  - **讲解，语音或文字二选一**（第十四轮决定）："把今天学的东西讲给一个比你小两岁的人听"。语音约 30 秒；文字约 50–150 字；
  - 一句话的人机协作说明。
- **防外包：**文字比语音更容易直接让 AI 代写，所以讲解的提示里固定带两个"只有自己才写得出来"的要素：**①一个你自己想到的例子，②你原来哪里不懂、现在怎么懂了。**AI 审核时，如果讲解明显是 AI 腔调、没有个人例子，就给低档（不直接驳回，避免误伤）。语音和文字的奖励相同，让孩子按自己的习惯选。
- **AI 审核：**检查三件事：讲的内容和证据是否一致；是不是真的在解释，而不是照抄、照念；有没有明显错误。通过即发放奖励（赛季玩家得粮草），同时保存各能力档位、知识标签，并生成修行日志的知识卡片。
- **模板（初稿，6 个）：**
  1. 用 AI 学了一个新知识；
  2. 对 AI 技术的一个新了解；
  3. 兴趣上的一次进展；
  4. 生活中的一次实践（做饭、修东西、整理）；
  5. 发现身边的一个问题；
  6. 读 / 看了一个作品，提出一个好问题。
- 每人每周最多计 4 次（和粮草规则一致）。第十七轮确认：**每天最多计 2 次、每周最多计 4 次**（模拟见《试运行内容库》8.3）。超过上限仍可提交、进修行日志但不产粮草——第二十三轮确认（修行日志就是孩子的日记）。

## 5. 主线任务（v1.1 起）
- **随时可做，节奏由孩子自己掌握**；赛季中和休赛期都可以做。
- **个性化 = 扬长 + 自选：**系统从孩子最强的两项能力和兴趣 track 里推荐 3 个主线任务，孩子也可以从完整任务库里自己挑。
- 每个境界都有自己的主线任务池，难度逐级提高。
- 评估：AI 初评 + 人工复核（或由评审员复核，待评审员训练轨成熟后）。

## 6. 境界（Tier）与升阶（v1.1 起）

### 6.1 世界观与命名（用户已确认）
以《西游记》为大世界观，借用修仙的境界感，但不照搬原著情节。每个大境界分初期 / 中期 / 后期三个小层，共 18 个小层。

| 境界 | 西游称号 | 大致含义 |
|---|---|---|
| 一境 · 石胎 | 仙石灵胎 | 起点，所有人从这里开始 |
| 二境 · 出世 | 花果山石猴 | 能完成基础任务 |
| 三境 · 求道 | 方寸山弟子 | 能完成第一类主线任务 |
| 四境 · 筑基 | 美猴王 | 至少两项能力较强 |
| 五境 · 金丹 | 齐天大圣 | 有代表作品，可申请评审员训练轨 |
| 六境 · 证道 | 斗战胜佛 | 高阶，可担任评审员 |

（一境原名"灵石"，与资源名重复，第十三轮改为"石胎"。）

### 6.2 起点
**所有人从一境开始，不按年级定起点。**有的孩子虽然在五六年级，真实水平可能只有二三年级；大孩子自然会升得更快。

### 6.3 升阶条件（初稿，数值待用试运行数据定）
1. 总经验达到本境界的门槛；
2. **扬长但不偏科：**至少 2 项能力达到本境界的要求，其余能力达到上一境界的要求；
3. 作品集：本境界完成 N 件主线作品；
4. **升阶答辩**（见第 7 节）。

### 6.4 境界解锁什么
- 赛季可携带的法宝档位和数量（凡品 → 灵品，数量严格限制）；
- 兴趣 track 栏位（1 → 3）；
- 挂机容量（第⑤步设计）；
- 主线任务的难度池；
- 评审员训练轨的申请资格（五境起）。

### 6.5 试运行数据如何折算
- v1.1 上线时，系统用最终公式重算每个孩子在试运行期间的所有记录，得出各能力经验和修为。
- 折算后可以直接进入对应的小层（例如一境中期），但**跨大境界仍然需要答辩**，保证每个境界都有一次"真实理解"的检验。
- 试运行玩家获得"首季元老"称号。

## 7. 升阶答辩：AI 语音考官（v1.1 起）

### 7.1 推荐的实现方式：轮流式（不做实时对讲）

```
孩子按住按钮录音回答 → 语音转文字 → 大模型读"孩子的作品 + 评分细则 + 前面的问答"
→ 生成下一个追问（屏幕显示文字，可选语音朗读）→ 共 4–6 轮
→ 大模型出答辩报告 → 通过 / 待定 / 不通过
→ "待定"和随机 10% 的"通过"转人工复核（听录音 + 看报告）
```

- **不用实时全双工语音：**轮流式技术简单、稳定、便宜，对孩子也更友好（可以想一想再按键回答）。
- **技术难度：**中等偏低。语音识别、大模型、语音合成都是现成的云服务，一个熟练的开发者大约 1–2 周能做出可用版本。真正的难点在于**追问的提示词设计**和**评分的一致性**，需要用一批真实作品反复调试。

### 7.2 成本估算（国内服务，按公开价格）
- **语音识别：**阿里云 Paraformer 每秒 0.00008 元，约合每分钟 0.005 元。
- **大模型：**豆包 1.6 在 0–32K 输入区间，输入 0.8 元/百万 tokens，输出 8 元/百万 tokens。
- **一次答辩**（孩子说约 5 分钟，6 轮追问 + 1 次出报告）≈ **0.1 元左右**；加上语音朗读追问也在 1 元以内。
- **每日任务的 30 秒语音审核：**每次约 0.01 元，一个孩子一个月约 0.2 元。
- 结论：**成本几乎可以忽略**，真正的成本在开发和调试。
- 实时语音作为以后的升级选项：火山引擎在 2026 年 6 月上线了豆包实时语音模型 3.0 的 API（邀测）；海外的 OpenAI 实时语音 API 大约 0.02–0.05 美元/分钟，但国内用户使用不便。

### 7.3 答辩报告长什么样（示意）

> **答辩记录 · 李同学 · 升阶：二境 → 三境 · 作品《为什么冰会浮在水上》（知识教学）**
>
> **问 1：**你在视频里说"冰的密度比水小"。能用你自己的话说说，什么叫密度吗？
> **答：**就是……同样大的一块东西，有多重。冰同样大的时候比水轻一点。
>
> **问 2：**很好。那为什么水结成冰以后反而变轻了？你视频里提到"分子排得更松"，能再讲讲吗？
> **答：**嗯……冰里面的水分子会拉成一个一个的格子，中间有空，所以占的地方大了。
>
> **问 3：**如果湖里的冰是沉下去的，冬天的鱼会怎么样？
> **答：**冰沉下去，上面的水又会结冰，最后整个湖都冻住，鱼就……就没地方待了。
>
> **问 4：**你做这个视频的时候，AI 帮了你什么？有没有哪一处你没有直接用 AI 的说法？
> **答：**AI 给我解释了氢键，但我觉得太难了，我就改成了"拉成格子"，然后自己画了图。
>
> ---
> **AI 报告**
> - 表达：3 档（能用自己的比喻解释抽象概念）
> - 思辨：3 档（能推演反事实情境）
> - 人机协作：4 档（能说清楚自己对 AI 内容做了取舍和改写）
> - 理解一致性：回答与作品内容一致，没有照念痕迹
> - **结论：通过**（置信度高，不需要人工复核）

### 7.4 防作弊
- **每题限时开口**（例如 15 秒内开始回答）；
- **追问聚焦孩子自己作品的细节**，题目每次都不同；
- 录音全部保存，可以抽查；
- 不是万无一失，但和"只交作品"相比门槛高了很多；真正理解自己作品的孩子，答辩很轻松。

### 7.5 兜底
如果 AI 答辩的效果不理想，升阶改为纯人工评判（用户已确认可以接受），AI 答辩作为预审。

## 8. 加速器（修炼状态，v1.1 起）
- **按"周"算连续：**一周内完成至少 4 天每日任务，这一周就算"没断"。
- **倍率：**每连续 1 周，倍率 +0.1，**上限 ×1.5**；断了以后回到 ×1.0。
- **定身符：**每月自动发 1 张，可以把连续记录"定住"一周，不掉倍率（借用孙悟空的定身法）。
- 加速器作用于个人经验和灵石，**不作用于赛季粮草和团队分**（保持赛季公平）。
- 为什么不用"连续签到指数增长"：会制造焦虑；会惩罚生病、住校的孩子；奖励的是打卡而不是学习。
